Admin — contact sheet

The management UI a non-technical coach uses to run the site: the words on each page and the order sections appear in, the ebooks, enquiries, orders, images, and who can sign in. Drawn light and calm — the opposite of the dark public site — on the same 1280 × 800 desk shell, plus one phone frame for the responsive collapse.

The source of truth for the admin's layout and controls. Every value is a token or a class in design/mockups/system.css (the --adm-* set, mirrored from src/libs/adminTheme.ts); the admin classes are scoped under .admin. The built screens match these frames.

What these frames fix. The main area breathes: 40px top and 48px side padding inside a 1040px column, so the heading sits off the top edge and the header action never jams the corner. Every dropdown is a themed react-select — a control with a chevron and a white menu with a ticked selection — not a bare native <select>.

Dashboard

The first screen after sign-in: what is on the site right now, and the newest enquiries. It sets the spacing every admin screen uses.

Pages & text

Edit the words on a page and reorder or hide its sections. The page picker is a themed react-select, drawn open so the menu style is a decision.

Team & access

Who can sign in and what each person can do. The role control is a react-select in the table cell; the last owner can never be removed.

Invite a teammate

The modal for adding a person: name, email, role (react-select), and a temporary password. One primary action sends it.

Settings

How you sign in, and the non-secret email settings the admin can change without a redeploy. Real secrets stay in the deployment's environment.

On a phone

The admin is desktop-first, but it has to work on a phone: the rail collapses to a top bar with a menu, and the padded column becomes the screen.
